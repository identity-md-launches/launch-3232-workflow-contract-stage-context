# The Firm website rules

Built in the same order as the launch of SPEC.md, against the addresses of that launch (Robinhood Chain 4663); LpGovernor, PriceGuard and Burner addresses are read from LpDesk's views.

- First screen of the home page: directly under the logo, the slogan "Don't work for the firm. Let the firm work for you." in exactly this text. (fail, don't change)
- First screen of the home page: a main button "Buy NOTSTOCK with ETH" opening https://app.uniswap.org/swap?chain=robinhood&inputCurrency=ETH&outputCurrency=<NOTSTOCK address>, the address built from this launch's NOTSTOCK address, never typed by hand. (fail, don't change)
- Any NOTSTOCK buy form on the site shows the same "Buy NOTSTOCK with ETH" link next to the wallet's IMD balance, so a wallet with no IMD, or an amount above its IMD balance, always has this path to buy. (fail, don't change)
- All addresses and numbers are fixed; if a step cannot be met, fail instead of changing them.
- Every page reads FirmVault, LpDesk, LpGovernor, PriceGuard, and Burner of this launch through public RPCs; the site stores, signs and relays nothing. (fail, don't change)
- Home page: the NOTSTOCK/IMD price, FirmVault's buyback bucket balance, its undistributed IMD and NOTSTOCK with a Distribute button for any connected wallet, and the 25/25/25/25 fee split, LpDesk's open positions and their value, its top-up and buyback baskets per token, the project wallet's received total, and the latest weekly report (fee receipts, buyback executions, dead-address balance change), read live from chain. (fail, don't change)
- "Burn" page: Burner's NOTSTOCK balance, total burned (the dead address's NOTSTOCK balance), a Burn button active for any connected wallet when Burner's balance is above zero, and Deposit: a NOTSTOCK amount field with the wallet's NOTSTOCK balance shown and a Max button, sending a plain transfer to Burner; an amount above the wallet's balance is blocked in plain English before signing. (fail, don't change)
- "LP Desk" page: the connected wallet's staked balance with Stake/Unstake buttons, every open and past proposal with its for/against weight, quorum progress, veto and execute deadlines, and a Propose button gated at the 0.1% staked threshold, offering AddVenue (a position manager address and its kind) besides the kinds below, with every listed venue shown from venues(); an Execute button once a proposal's veto window has passed unvetoed; a Passed proposal shows the time left until it expires, and an expired one shows the status Expired with no Execute button. (fail, don't change)
- Bridge on the "LP Desk" page: every bridge record (adapter, destination chain id, destination LpDesk) and every BridgeOut is listed; Propose offers AddBridge and BridgeOut with the same vote and veto, and execute() of a BridgeOut shows the LayerZero fee the executing wallet pays. (fail, don't change)
- Setup on the "LP Desk" page, for any connected wallet: every LpDesk module with its deployed state and, while one is not deployed, a Deploy button calling deployModule(kind, creationCode); each module's creation code from this launch's build is embedded in the site, so Deploy works in one click with no file to supply. (fail, don't change)
- Setup order: a Fund GenesisSplitter button (NOTSTOCK transfer to GenesisSplitter) is inactive until every LpDesk module is deployed; once GenesisSplitter holds 60% of supply and FirmVault is the pool fee recipient, a Register button calling PriceGuard.registerNotStock(launchNumber), then a Split button calling GenesisSplitter.split(); each button is hidden once its call has succeeded. (fail, don't change)
- Every inactive Setup button shows its reason in one line of plain English, such as "Deploy all modules first", "Deploy PriceGuard first", "Fund GenesisSplitter first" or "Register first". (fail, don't change)
- launchNumber is this launch's number, built into the site and not editable; every setRequester or registerNotStock call the site offers uses only that number. (fail, don't change)
- "Operator" section inside the "LP Desk" page: its controls are visible and active only when the connected wallet is LpDesk's current operator; every other wallet sees the same data read-only, with no active operator button. (fail, don't change)
- Operator form fields: pair (asset picked from PriceGuard's asset list only, no address entry), venue (picked from PriceGuard's venues() read live from chain, never a hard-coded list, each shown with its name if it is one of the three of SPEC.md section 2b and its address otherwise), fee tier (fee on V3 and V4, tick spacing on CL), a price field prefilled with the pool's current price when the pair has a pool on that venue and empty, typed by hand, when it has none, with the note "Open fails if the pool price differs from this price by more than 0.5%", price range "from" and "to" in asset units per NOTSTOCK with the current pool price shown, presets narrow +/-20%, medium +/-50%, wide 2x (from half to double the current price) and manual entry, and a NOTSTOCK amount with LpDesk's free balance shown and a Max button. (fail, don't change)
- Operator preview before any signature: the lower and upper ticks, the NOTSTOCK (and asset) amount going into the position with its 99.5% minimums, and the balance left in LpDesk after it. (fail, don't change)
- Operator buttons: Open, active only during the 7-day bootstrap of SPEC.md section 2, with its end time shown; Shift range, Collect fees and Close, active at any time for the operator, on every open position; Propose with the same fields (OpenPosition) or an asset address (AddAsset) once the bootstrap has ended, and AddVenue (a position manager address and its kind V3, CL or V4) at any time. Shift range and close transactions carry per-asset minimum outs from a slippage field the operator sets, with the expected outs shown. Top up on every open position: an asset amount field with that asset's top-up basket shown and a Max button, the pool's current price and the 99.5% minimum liquidity filled in. Buyback on every open position whose asset is not IMD: an asset amount field with that asset's buyback basket shown and a Max button, the expected NOTSTOCK out shown and a minimum out from a slippage field the operator sets; an amount above either basket is blocked in plain English before signing. Burn: a NOTSTOCK amount field with LpDesk's free NOTSTOCK balance shown and a Max button, sending to the dead address; amount above the free balance is blocked in plain English before signing. (fail, don't change)
- Every operator action is a transaction signed by the connected browser wallet; the site stores, signs and relays nothing. (fail, don't change)
- Site test: with a non-operator wallet connected, no operator button is visible or active; with the operator wallet connected, Open is active during the bootstrap window and inactive after its end time, and Close is active on every open position both during and after the bootstrap; the venue picker lists exactly PriceGuard's venues(), and after an executed AddVenue on a fork the new venue appears with no site change. (fail, don't change)
- No third-party script, font or frame loads before the user presses Connect. (fail, don't change)
- A contract revert (every custom error of the SPEC.md contracts and of the launch factory, such as NotRequester) is shown as its meaning in plain English, never as a connection error. (fail, don't change)
- With no wallet connected, a wallet value reads "Connect wallet"; a value of an undeployed module reads "After setup"; never "Unavailable". (fail, don't change)
- The network line has a space on both sides of "·", as in "Robinhood Chain · Block 123". (fail, don't change)
- Any fee or flow diagram on the site is drawn from the rules of SPEC.md.
